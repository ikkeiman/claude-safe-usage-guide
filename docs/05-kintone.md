# 05. kintone のカスタマイズを AI で作るとき

AI に依頼すれば、kintone のカスタマイズ用 JavaScript は数分で作れます。だからこそ、**中身を見ないまま本番に入れやすい**のが一番の危険です。
この章は、kintone の開発元が開発者向けに示している確認の観点（2026 年の開発者向けセッションと cybozu developer network の記事）と、作者の実装経験をまとめたものです（[K0]〜[K9]、[O3][O4]）。

> 注意: cybozu developer network の記事本文は、この資料を作った環境から直接は開けませんでした。API 名と記事の要点は検索結果で確認しています。使う前に各リンク先で最新の仕様を確かめてください。

## 進め方（人と AI の役割分担）

開発元のセッションと記事では、次の流れを繰り返すことが示されています（[K0][K2]）。

1. **目的と条件は人が決める**（何を実現するか、AI に何を任せ、何を任せないか）
2. AI にコードの生成やエラーの分析を依頼する
3. 出てきたコードを **AI と人で一緒に確認**する
4. **採用するか直すかは人が決める**。直すなら 2 に戻る

AI に渡す情報として、依頼内容に加えて**アプリの説明（フィールドの種類とフィールドコード）**を渡すと、取り違えが減ります。
存在しない API や古い書き方を避けるために、公式ドキュメントを参照させる MCP サーバー（kintone のドキュメント用 MCP サーバー）を使う方法も紹介されています（[K3]）。

## よく起きるミス（動かない）

| # | ミス | 確かめ方 |
|---|---|---|
| E1 | **フィールドの種類の取り違え**（ラジオボタンをチェックボックスとして扱う、など） | フォームの設定と、コードが前提にしている種類を見比べる |
| E2 | **存在しない選択肢の値**を登録しようとする | 選択肢の値を設定画面からそのまま渡す |
| E3 | **フィールド名とフィールドコードの取り違え**（日本語の表示名を使ってしまう） | コードの中のキーがフィールドコードになっているか |
| E4 | 既存のカスタマイズ、プロセス管理、**ゲストスペース**との衝突 | ゲストスペースでは API の URL が変わる。`kintone.api.url(パス, true)` を使う |

## 動くけれど直したいこと（アンチパターン）

| # | AI が書きがちなもの | 置き換え先 | 理由 |
|---|---|---|---|
| A1 | 画面の要素を**クラス名で探して直接書き換える** | 詳細画面は `kintone.app.record.setFieldStyle()`、一覧は `kintone.app.setRecordListStyle()`（2026 年 4 月追加）、表示・非表示は `kintone.app.record.setFieldShown()` | kintone 内部のクラス名はアップデートで変わりうる（[K4][K5][K6]） |
| A2 | ブラウザ標準の `confirm()` / `alert()` | `kintone.showConfirmDialog()`、`kintone.showNotification()`（2025 年 9 月追加。確認ダイアログは PC のみ） | 見た目がずれ、表示中は他の処理が止まる（[K7]） |
| A3 | 管理者の**メールアドレスをコードに直書き**して権限を判定する | 権限を問い合わせる API（例: レコードのアクセス権の評価 `/k/v1/records/acl/evaluate.json`）や、アプリ・スペースの権限設定に任せる | 権限を変えたときにコードの修正が要らない（[K8]） |
| A4 | 日付の条件を **JavaScript で計算してクエリに埋める** | クエリの関数 `TODAY()`、`FROM_TODAY(数, 単位)` など | 日付の境目やタイムゾーンを kintone 側で正しく扱える（[K9]） |
| A5 | 外部サービスへ **`fetch` で直接送る** | `kintone.proxy()`。認証情報が要るなら**プラグイン**にして `kintone.plugin.app.proxy()` と `setProxyConfig` | ブラウザの CORS 制限を避け、認証情報をブラウザに出さない（[K10]） |

## セキュリティの観点（必ず見る）

| # | 見ること | 置き換え先・対策 |
|---|---|---|
| S1 | 利用者の入力を `innerHTML` にそのまま入れていないか | `textContent` を使うか、エスケープしてから入れる（作者の [kintone-js-utils](https://github.com/ikkeiman/kintone-js-utils) の `html` テンプレートは自動でエスケープする） |
| S2 | **API トークンやパスワードを JavaScript に直書き**していないか | カスタマイズ JS はアプリを開ける人なら誰でも読める。プラグインの proxy 設定に置く（[K1][K10]） |
| S3 | 認証情報を `localStorage` など推奨されない場所に保存していないか | 保存しない。プラグインの設定に置く（[K1]） |
| S4 | リンクに利用者の入力を入れるとき、`javascript:` で始まる URL を止めているか | URL の形式を検査してから使う |
| S5 | 外部に送る中身に、個人情報や不要な項目が含まれていないか | 送る項目を必要なものに絞る（[06](06-sensitive-data.md)） |

## 作者が kintone で繰り返し使っている書き方

作者が公開している部品集 [kintone-js-utils](https://github.com/ikkeiman/kintone-js-utils) とプラグイン [kintone-dropbox-plugin](https://github.com/ikkeiman/kintone-dropbox-plugin) は、上の観点の多くを部品にしたものです（[O3][O4]）。

| 現場で起きること | 部品の答え |
|---|---|
| `offset` を使う全件取得は 1 万件で止まる | `$id` の順に取る |
| 一覧で直接編集 → 一部失敗 → 押し直すと二重に追加される | 100 件ずつ保存し、保存済みの印を付ける |
| 2 人がほぼ同時に書くと、先の人の行が消える | 読んだときの版番号を付けて書き戻し、競合したら読み直す |
| 外部 API の秘密をブラウザに出したくない | App secret を `setProxyConfig` に保存し、kintone のサーバー側で付ける |

AI に依頼するときに「この部品を使って」と指定すると、上の事故を最初から避けられます。
