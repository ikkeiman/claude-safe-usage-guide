# 06. 個人情報・機密を送らない、残さない

生成 AI を業務で使うときの一番大きな事故は、**送ってはいけないものを送る**ことです。そして二番目は、**残してはいけない場所に残す**ことです。

## 送る前に

| 区分 | 例 | 扱い |
|---|---|---|
| 送らない | 個人番号、カード番号、口座番号、健康情報、未公開の人事・取引条件、認証情報 | 入力しない。混ざっていたら止める |
| 伏せて送る | 氏名、電話番号、メールアドレス、住所 | `<氏名1>` のように置き換えてから送る |
| 送ってよい | 公開済みの情報、匿名化した集計、架空のデータ | そのまま使える |

- **止める仕組みを入口に置く**: 作者の [llm-guard-gateway](https://github.com/ikkeiman/llm-guard-gateway) は、入力を「ルール → 固有表現抽出 → ローカル LLM」の 3 段階で検査し、個人情報を伏せてから外部の LLM に送るプロキシです。合成データ 500 件で、既定の設定は見逃し 2.8%・止めすぎ 0%（参考値）でした（[O1]）
- **禁止より「伏せて使わせる」**: 全面禁止にすると、現場は使わなくなるか、隠れて使います。伏せた形で使える道を用意する方が、結果として安全です
- **確かめられる番号は機械で決める**: 個人番号の検査数字やカード番号の Luhn のように、機械的に確かめられるものは LLM の判断に任せません（[O1]）

## 読ませる前に（Claude Code・MCP）

- `.env`・鍵・認証情報のファイルを**読めない設定にする**（[03](03-claude-code.md) の deny ルールと hook）
- MCP サーバーに渡すフォルダは、**読ませてよいものだけを集めたフォルダ**にする
- テストデータは**架空のデータ**で作る（Faker などで生成し、seed を固定する）

## 残さない

- ログに**本文を書かない**。残すのは、いつ・誰が・どの操作・どの種類の情報が・何件、まで（[00](00-principles.md) P5）
- 検索語やパスを記録したいときは、ハッシュの先頭だけを残す（同じものかは追えるが、中身は残らない）（[O2]）
- 承認待ちのために本文を一時的に持つ場合は、**解決した時点で消す**（[O1]）

## プラグイン・カスタマイズの秘密

- カスタマイズの JavaScript に書いた値は、**そのアプリを開ける人なら誰でも読めます**
- 外部 API の秘密は、プラグインにして `kintone.plugin.app.setProxyConfig` で保存すると、**kintone のサーバー側で付けられ、ブラウザには届きません**（[K10][O4]）
