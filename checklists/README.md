# チェックリスト（1 枚もの）

印刷して手元に置く用。詳しい理由は各章を見てください。

## A. Claude Desktop に道具（MCP サーバー・拡張機能・コネクタ）を入れる前に（[02](../docs/02-claude-desktop.md)）

- [ ] 出所が分かる（公式・自社・信頼できる発行者）。リポジトリとライセンスがある
- [ ] 書き込み・削除・送信・実行の道具が、本当に必要なものだけ
- [ ] 触れる範囲（フォルダ・アカウント）が必要最小
- [ ] 毎回取ってくる起動方法（`npx -y` / `uvx`）なら、版を固定した
- [ ] トークンを設定ファイルに平文で書いていない
- [ ] ログに本文や検索語を書かない
- [ ] 「常に許可」は、中身を確かめた読み取り専用の道具だけ

## B. Claude Code を使い始めるとき（[03](../docs/03-claude-code.md)）

- [ ] `.env`・鍵・認証情報を `Read(...)` の deny で読めなくした
- [ ] 送信（`curl` `wget`）と強制 push を deny、公開系（`git push` `npm publish`）を ask にした
- [ ] 危ない操作を止める hook を入れた（[templates/claude-code](../templates/claude-code)）
- [ ] macOS / Linux ならサンドボックスを有効にした。Windows なら WSL2 やコンテナを検討した
- [ ] `bypassPermissions` / `--dangerously-skip-permissions` は、隔離した環境の中でしか使わない
- [ ] `/permissions` で入っているルールを確かめた
- [ ] プロジェクトの `.mcp.json` のサーバーは、中身を見てから承認した

## C. AI が書いたコードを採用する前に（[04](../docs/04-review-ai-code.md)）

- [ ] 自分で説明できる
- [ ] 使っている API・関数が実在し、非推奨でないことを公式ドキュメントで確かめた
- [ ] テスト・lint・型検査が通る。テストが仕様を表しているかを人が見た
- [ ] 秘密情報が混ざっていない
- [ ] 頼んでいない範囲を変えていない
- [ ] 外部への送信の宛先と中身を確かめた
- [ ] 検証環境で試し、戻し方を決めた

## D. kintone のカスタマイズを AI で作ったら（[05](../docs/05-kintone.md)）

- [ ] フィールドの種類・フィールドコード・選択肢の値が、アプリの設定と一致している
- [ ] 画面の要素をクラス名で直接いじっていない（スタイル・表示切替の API を使う）
- [ ] `alert` / `confirm` ではなく kintone のダイアログ・通知の API を使っている
- [ ] 権限をメールアドレスの直書きで判定していない
- [ ] 日付の条件はクエリの関数（`TODAY()` など）で書いている
- [ ] 外部への送信は `kintone.proxy()`、秘密が要るならプラグインの proxy 設定
- [ ] `innerHTML` に利用者の入力をそのまま入れていない
- [ ] API トークンやパスワードを JavaScript に書いていない
- [ ] ゲストスペースでも動く（`kintone.api.url(パス, true)`）

## E. 入力する前に（[06](../docs/06-sensitive-data.md)）

- [ ] 個人番号・カード・口座・健康情報・認証情報・未公開の情報が入っていない
- [ ] 氏名・連絡先・住所は伏せた
- [ ] テストには架空のデータを使っている
